# Security Policy

## Reporting a vulnerability

Please use the repository's private **Report a vulnerability** option on GitHub when available. Do not disclose credentials, private repository contents, or an unpatched vulnerability in a public issue.

Include the affected file or workflow, impact, reproduction steps, and any suggested mitigation. You should receive an acknowledgement through GitHub after the report is reviewed.

## Scope

Security reports are especially useful for unsafe command execution, unintended GitHub Project updates, credential exposure, permission escalation, or behavior that can modify an issue other than the one selected.

These skills invoke local agent tools and the authenticated GitHub CLI. Users are responsible for reviewing the files, limiting GitHub token scopes, protecting their environment, and choosing appropriate Claude Code or Codex permissions.
